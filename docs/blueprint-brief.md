| Media | VdoCipher (Widevine/FairPlay DRM + dynamic user-ID watermark). Private S3 + CloudFront for other files. No videos/binaries in Postgres. |

Subscription debits ≤ ₹15,000 to stay within RBI e-mandate no-AFA limit. ◆ Webhook path `/api/v1/webhooks/{provider}`, routed by CloudFront/ALB straight to `api-webhooks` (never through the BFF); stale or out-of-order events, like every other state-changing event, are applied only from a server-side re-fetch (ADR-0006 v0.4; `is_stale` is a monitoring flag only). | Sessions | Server-side opaque sessions (≥128-bit random, only SHA-256 hash stored), `__Host-td_session` cookie: Secure, HttpOnly, SameSite=Lax, Path=/. CSRF: signed double-submit + Fetch Metadata. ◆ The BFF (`web`) issues and validates `td_csrf`; `TD_CSRF_KEY` exists only in `web` (ADR-0010). ▲ Device identity: `__Host-td_device` cookie (128-bit random, identifies a browser profile, no PII); stored only as **keyed HMAC-SHA-256** (`devices.device_key_hash`). Login identifiers are stored as HMAC (`login_attempts.identifier_hash`). Verification, password-reset and invite tokens: SHA-256 only. Sessions are never bound to IP. ▲ Every session has a `scope`: `full`, `restricted` (L3) or `status_only` (L4). ◆ Pending statuses: `pending_mfa`, `pending_device_otp`, `pending_session_choice` (at the session cap, waiting ≤ 5 min for the user to choose which session to end). ✦ Session cookie `Max-Age` = time to absolute expiry (registered lab devices: browser-session cookie). `k_device` and `k_login` HMAC keys are versioned (`key_version`) so they can be rotated without breaking lookups. Postgres is the session source of truth; Redis `cache` is a read-through copy. |
| Timeouts (idle/absolute) | Students 60 min / 24 h ✦ (with "remember device": silent re-issue only on a top-level user navigation on a trusted device, within a fixed 30-day ceiling from the last full authentication that never slides; the re-issued session is AAL1); staff 30 min / 12 h; finance, security_reviewer, super_admin 15 min / 8 h + mandatory MFA (TOTP/passkey). ▲ Tier mapping (`session_tier`): `student`; `staff` = college_coordinator, trainer, content_manager, placement_mentor, support_agent; `privileged` = finance_admin, security_reviewer, super_admin. Tier = most privileged active grant at login; a grant change forces re-login. Registered college lab devices: 30 min idle, no remember-device. ✦ The idle timer is extended only by engaged activity: every authenticated route declares an idle effect (`extends`, `engaged_only`, `neutral`); keepalives, polling and prefetches never extend it; an in-progress timed attempt holds the session until `deadline_at + grace + 5 min`; absolute timeouts are never extended. |
| ▲ MFA and step-up | MFA mandatory for all staff and privileged tiers *(PO-06)*; factors passkey (preferred) or TOTP; SMS and email never accepted for staff/privileged *(PO-05: passkey-only for privileged is proposed)*; break-glass passkey only. Step-up freshness (`auth_sessions.last_step_up_at`): **5 min** for privileged actions (refund, role grant, policy change, case decision, bulk export); **10 min** for other staff sensitive actions (incl. support session kills); **15 min** for student email/phone/MFA changes. |
| Passwords | NIST 800-63B-4: min 15 chars without MFA (8 with MFA), max ≥64, no composition rules, breached-password blocklist, Argon2id m=19456 KiB t=2 p=1 (argon2-cffi / pwdlib). ▲ Progressive back-off; hard disable after `login.hard_disable_after_failures` (default 50, max 100); pre-auth blocks do not count. |
| Device policy (default, configurable) | Max 3 registered (trusted) devices per student; max 2 concurrent active sessions; max 1 concurrent video playback stream; max 2 device replacements per 30 days (self-service); new device ⇒ email/SMS OTP verification. ▲ **Each browser profile counts as a device** *(PO-02)*; registered college lab devices do not count toward personal device caps (session caps still apply). Trusted devices expire after 90 days of inactivity (does not consume a replacement). ▲ **Assessments:** an in-progress attempt is bound to one session; another session gets a read-only "open on another device" view and may rebind after explicit confirmation (OTP required when restriction level ≥ L2), max 2 rebinds per attempt ✦; re-login on the same device (same `__Host-td_device`) re-attaches the attempt without consuming a rebind or needing OTP (attempt event `reattach_same_device`); sessions holding an in-progress attempt are never auto-evicted by the session cap; proctored drives need a trainer override *(PO-08)*. ◆ Attempt events `rebind_requested`/`rebind`/`rebind_refused` (no `session_takeover`/`device_switch`). Autosave: 5 s debounce, at most **10 s** after the first unsynced change. A refused second stream returns `409 playback_conflict`. |
| Minors (<18) | Age gate at signup. Under-18 accounts need verifiable parental consent (or college acts as data fiduciary with Tech Drona as processor). For minors: NO behavioural risk scoring / account-sharing profiling / targeted ads; only deterministic caps (device/session/stream limits) and security-necessary logs. ▲ **Unverified age ⇒ minor treatment** (`users.is_minor` defaults to true until an age determination is recorded in `age_verified_at`; `users.privacy_tier` is derived). "Security-necessary" includes deterministic account-takeover controls (throttling, breached-password reset, cookie-replay revoke) but never an accumulated score ✦; no `risk_evaluations` rows of any family are written for minors; deterministic takeover actions are recorded as `security_signals`. On turning 18, adult processing starts only from the adult consent date; no back-fill. |
| Risk engine | Explainable rule-based scoring v1 (versioned rules), graduated levels L1–L4, never permanent ban on IP/fingerprint alone, human review + appeal, second-person approval for L4 lifts on high-risk cases. ML only later. ▲ The engine may apply L1–L3 automatically: L3 only behind multi-day, multi-category, separated-use gates, **or** through a configured high-confidence rule (HC-01/HC-02, adults only) that has completed ≥ 14 days of shadow and dual approval and is enabled by the 🔒 switch `risk.hc.auto_restrict_enabled` (default false); an automatic circuit breaker returns an HC rule to shadow on a false-positive spike. **L4 is applied by a human only** — the engine can only recommend it. Network evidence is capped below L2. Rule versions need ≥14 days shadow + dual approval. High-risk = `security_cases.is_high_risk` (unblock workflow §5). ✦ Owner (OTP/passkey) verification never discounts overlapping use on two distinct fixed-line networks at the same time (separation class S3). Emergency move of `risk.mode` to `shadow` (or HC rules off) needs one `security_reviewer`/`super_admin` plus ratification by a second person within 24 h; any move toward enforcement is dual-approved. Engine-applied L3s can be lifted in bulk (Dual). Rule-key families: `SH-*`, `TO-*`, `HC-*`, `AB-01..12`, `IN-01..03`, `cap.*` (`account-security-and-risk-engine.md` §4). |
| ▲ Unblock request states | `draft`, `submitted`, `under_review`, `info_requested` (Additional information requested), `escalated` ("With senior reviewer"), `approved`, `rejected`, `closed` (with `closure_reason`). `escalated` added to the verbatim list *(PO-01)*. Logs min 1 year ✦ (security and operational logs purged at 13 months = 395 days); CERT-In 6-hour incident reporting; GST records 72 months. ▲ Canonical consent purposes (`consents.purpose`): `terms`, `privacy_notice`, `core_service` (item A, incl. basic learning-progress analytics), `security_monitoring` (item B, account-sharing detection; required for adult paid plans, withdrawal ⇒ deterministic-only mode *(PO-03)*), `analytics_personalisation` (item C, default off *(PO-04)*), `college_data_sharing` (D), `device_fingerprint` (E, Phase 2), `marketing_email`, `marketing_sms` (F), `assessment_integrity` (G, per test), `analytics_product` (H, adults, opt-in). ## 2. Module map (backend packages under `apps/api/app/modules/`)

`identity` (users, auth, MFA, verification, consents) · `sessions` (sessions, devices, concurrency, playback sessions) · `security` (signals, risk engine, restrictions, cases, unblock requests, trusted networks, security incidents) · `orgs` (organizations/colleges, batches, memberships, invitations, bulk imports) · `rbac` (roles, permissions, scoped grants) · `catalog` (courses, modules, lessons, resources, lesson→topic mapping) · `learning` (enrolments, progress, assignments, certificates) · `placement` (taxonomy, question bank, practice, company paths, recommendations, mentoring, résumés) · `assessments` (tests, sections, assignments, overrides, attempts, scoring, results) · `coding` (problems, test cases, submissions, judge-gateway, languages) · `commerce` (products, plans, prices, coupons, orders, payments, subscriptions, invoices, contracts) · `entitlements` (grants, history, access checks) · `analytics` (event ingest, sessionization, aggregates, mastery, item stats, security feed, reports, exports) · `notifications` (email/SMS/in-app) · `audit` (append-only, hash-chained audit log) · `support` (tickets, messages) · `media` (VdoCipher OTP/playback tokens, uploads; `playback_sessions` owned by `sessions`) · `admin` (platform config, `policy_settings`, `feature_flags`, approvals; privacy sub-package: rights requests, retention registry, erasure ledger).

Kernel (`core`): `outbox_events` (transactional outbox for all server-emitted domain events), `idempotency_keys`, `audit.record()` facade writing `audit_outbox`, `policy.get()`, rate limiting, clock.

▲ Cross-module rules:
- One writer per table (owner above / schema header). Other modules read through service interfaces.
- Domain events published via the outbox include at least `session.ended`, `account.restricted`, `restriction.lifted`, `consent.changed`, `age_tier.changed`, `entitlement.granted/revoked`, `attempt.submitted`; analytics consumes them.
- `security` never queries raw analytics tables. It uses `analytics.feeds.get_engaged_buckets(user_id, from, to)` (5-min buckets: device, session, activity kind) and `analytics.feeds.get_activity_summary(user_id, from_date, to_date)` (daily feed). Both return data only for adults with an active `security_monitoring` consent.
- `security` gates entitlements (never revokes them); lifting a restriction restores access with no commerce change.

`student`, `college_coordinator`, `trainer`, `content_manager`, `placement_mentor`, `support_agent`, `security_reviewer`, `finance_admin`, `super_admin`. Roles are granted with a scope: `platform`, `organization:{id}`, `batch:{id}`, or `course:{id}`. ▲ Session tiers per §1 Timeouts. `finance_admin` and `security_reviewer` are mutually exclusive; dual-control actions go through `approval_requests` (approver ≠ requester, 72 h expiry). ✦ Pending second-person case decisions are `approval_requests` rows (`security.case.decision`); `case_decisions` stores final decisions only. ◆ **Permission keys** come only from `docs/role-permission-matrix.md` (machine-readable copy `apps/api/app/core/authz/permissions.yaml`). Report exports: `report.export.request` (security_reviewer, finance_admin @platform; college_coordinator @own org; trainer @own batch) and `report.export.approve` for exports that need approval (approver ≠ requester): a second `security_reviewer` for security/monitoring exports (H1–H9, H12, per-user device/login history), `super_admin` for all others. ## 5. API conventions

Base `/api/v1` (◆ including webhooks: `/api/v1/webhooks/{provider}`). JSON, snake_case. Errors: RFC 9457 problem+json with `type`, `title`, `status`, `detail`, `code`, `request_id`. Pagination: cursor (`?cursor=&limit=`). Idempotency-Key header on all POSTs that create money/attempt/submission records (and unblock-request submission). ▲ Exception: `POST /api/v1/analytics/events` and `/analytics/events/beacon` (◆ max 100 events per request; authenticated ownership, no permission key) are idempotent per event (client UUIDv7 `event_id`, `ON CONFLICT DO NOTHING`) and do not take the header. ▲ The beacon route accepts a body-borne signed CSRF token plus `Sec-Fetch-Site: same-origin` (sendBeacon cannot set headers); every other route uses the standard CSRF header. Every endpoint declares required permission + scope. Blocked/restricted accounts are enforced in a single backend dependency (`require_active_principal`) applied to every authenticated router — not per-route opt-in. ▲ Sessions with `scope` `restricted` (L3) or `status_only` (L4) may call only routes tagged `account_status` (me, devices/sessions, cases and unblock requests, privacy requests incl. data export, billing view/cancel, support, logout) and, for L3, `l3_readonly` (read-only dashboard/progress, certificate list). ✦ The canonical tag set is `public`, `login_continuation`, `account_status`, `l3_readonly`, `mfa_enrolment`, `consent`, `default` (`api-specification.md` §1.4); tags may be declared in any module. Every authenticated route also declares an idle effect (`x-td-idle`: `extends`, `engaged_only`, `neutral`). Session scope is derived per request from the restriction state (`auth_sessions.scope` is a record only). Everything else returns 403 problem+json `code=account_restricted` with the case reference. A CI test fails if any authenticated route lacks the dependency or tag mapping. Attempts bound to another session return `409 attempt_bound_elsewhere`; a refused stream returns `409 playback_conflict`; ✦ an attempt start whose session would expire before `deadline_at + grace + 5 min` returns `409 session_too_short_for_attempt`. ◆ Step-up freshness missing → `401 step_up_required`; staff/privileged without an enrolled factor → `403 mfa_enrolment_required`; feature flag `platform.maintenance_mode` → writes return `503 maintenance` with `Retry-After` (GETs and health allowed). Playback routes: `POST /api/v1/media/playback-tokens`, `POST /api/v1/media/playback-sessions/{id}/heartbeat`.

### 8.2 Local development ports

Docker Compose (`docker-compose.yml`) publishes host ports from env with these defaults: Postgres `TD_PG_HOST_PORT=5432`, Redis cache `TD_REDIS_CACHE_HOST_PORT=6379`, Redis queue `TD_REDIS_QUEUE_HOST_PORT=6380`, Mailpit SMTP `TD_SMTP_HOST_PORT=1025`, Mailpit UI `TD_MAILPIT_UI_HOST_PORT=8025`, S3 (SeaweedFS, container port 8333) `TD_S3_HOST_PORT=9000`, api `TD_API_HOST_PORT=18000`, web `TD_WEB_HOST_PORT=13000` (8000/3000 avoided). On hosts where 5432/6379/6380 are taken, the documented overrides are **15432 / 16379 / 16380**, and the matching `DATABASE_*_URL` and `REDIS_*_URL` values must change with them (`docs/local-development.md`).
