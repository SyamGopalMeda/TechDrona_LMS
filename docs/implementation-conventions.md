# Implementation Conventions (binding for all implementation agents)

Owner: Integration Lead. Read with `docs/blueprint-brief.md` (v0.4, contracts), `docs/api-specification.md`, `docs/database-schema.md`. Do not edit this file; propose changes in your final report.

## 1. Repository layout

```
apps/api/                 FastAPI modular monolith (Python 3.12+; local machine has 3.13)
  pyproject.toml          deps + tool config (ruff, mypy, pytest)
  app/main.py             app factory; auto-discovers module routers (do NOT hand-register)
  app/core/               config, db, security primitives, errors, logging, deps (Foundation owner)
  app/modules/<module>/   one package per brief module: models.py, schemas.py, service.py, router.py, policies.py, tasks.py
  migrations/             Alembic (env.py + versions/)  — path fixed by ADR-0009
  tests/                  tests/<module>/..., tests/conftest.py (Foundation owner)
apps/web/                 Next.js (App Router, TS, Tailwind) — BFF route handlers under app/api/
packages/design-tokens/   tokens.json + tailwind preset (UX owner)
infra/                    Terraform skeleton (DevOps)
docker-compose.yml        local postgres 16 + redis 7 (+ mailpit for dev email)
.github/workflows/        CI
scripts/                  dev scripts; seeds live in apps/api/app/seeds/ (dev/demo ONLY, labelled)
```

## 2. Ownership rule

One agent owns a directory at a time; the assignment is in the agent's prompt. Never edit files outside your assigned paths. If you need a change elsewhere (e.g. a new core helper), implement a local helper in your module and list the request in your final report.

## 3. Module auto-discovery

`app/main.py` imports every `app.modules.<name>.router` that exposes `router: APIRouter` and includes it under `/api/v1`. Models are discovered via `app.modules.<name>.models` imported in `app/core/models_registry.py` by package scan, so Alembic autogenerate sees them. Modules therefore never edit `main.py`.

## 4. Migrations (parallel-safe)

- Each module has its OWN Alembic branch: first migration in a module uses `branch_labels=("<module>",)` and `down_revision=None` + `depends_on=("core_base",)` (the Foundation base revision, which creates extensions, schemas, roles, helper functions such as `app.current_org_id()`).
- Later migrations in the module chain off that module's previous revision.
- Cross-module FKs: add `depends_on` the other module's revision id that creates the referenced table.
- Revision ids: `<module>_<NNNN>` (e.g. `identity_0001`). File names `<module>_<NNNN>_<slug>.py`.
- Apply with `alembic upgrade heads`. Migrations are hand-reviewed DDL (autogenerate allowed as a draft). Every tenant table gets RLS + FORCE per database-schema.md.
- Only the owning module agent writes its module's migrations.

## 5. Shared runtime contracts (implemented by Foundation in app/core)

- `get_db()` async SQLAlchemy session; `tenant_context(session, principal)` runs `SELECT set_config('app.user_id', …, true)`, `app.org_ids`, `app.roles`, `app.privacy_tier` per transaction.
- `Principal` dataclass (user_id, session_id, org memberships, role grants, is_minor, restriction level, mfa_level, step_up_at).
- `require_active_principal` dependency — every authenticated router uses `router = APIRouter(dependencies=[Depends(require_active_principal)])` or an explicit route tag allow-list (`account_status`, `l3_readonly`, `login_continuation`). A test enumerates routes and fails if any authenticated route lacks it. Foundation implements it against an interface; Identity/Sessions/Security fill in the lookup functions.
- `require_permission("perm.key", scope=...)`, `require_step_up(window_s)`.
- Errors: raise `ProblemError(code, status, title, detail, **ext)` → RFC 9457 problem+json with `request_id`.
- Idempotency: `idempotent(request)` helper backed by `idempotency_keys` table.
- Outbox: `emit_event(session, type, payload)` → `outbox_events`; `audit(session, actor, action, target, data)` → `audit_outbox`.
- Time: all timestamps `timestamptz` UTC; IDs UUIDv7 (`app.core.ids.uuid7()`); money as integer paise.
- Secrets/config from env via pydantic-settings; names per `.env.example`.

## 6. Testing

- pytest + pytest-asyncio + httpx AsyncClient. Integration tests use the real Postgres from docker-compose (`TEST_DATABASE_URL`, separate database `techdrona_test`), migrated with `alembic upgrade heads` once per session; each test runs in a transaction/savepoint rolled back afterwards (or truncation fixture).
- Do not mock the database for business workflows. External providers (Razorpay, VdoCipher, Judge0, SES, SMS) are behind adapter interfaces with a `fake`/`sandbox` adapter selected by env for local+CI; the fake must be clearly named and never used when `APP_ENV=production` (startup check).
- Each module ships tests for: happy path, permission denials (incl. cross-tenant), restricted principal denial, validation errors.
- Web: Vitest for units, Playwright for E2E.

## 7. Commands (Windows dev machine; also used in CI)

- `docker compose up -d` (postgres, redis, mailpit)
- `cd apps/api && python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"`
- `cd apps/api && .venv/Scripts/alembic upgrade heads`
- `cd apps/api && .venv/Scripts/pytest`
- `cd apps/web && npm install && npm run dev | build | test`

## 8. Honesty rules

Mark features Implemented only when backend-enforced, persisted and tested. Report what you ran and the real results. No silenced/skipped failing tests. External integrations without credentials are "Implemented (adapter + fake), not verified against provider".
