## Requests

1. **core (`app/core/middleware` / maintenance, ADM-17):** gate `platform.maintenance_mode` with `await app.modules.admin.flags.cached_flag_enabled("platform.maintenance_mode")`, returning `503 maintenance` for non-GET requests. **sessions/identity:** gate fingerprint collection on `flags.flag_enabled(session, "risk.fingerprint_collection", user_id=...)` when it is built.
2. **core (`app/wiring.py`, optional hardening):** add `ent.register_outbox_handlers()` inside `wire_all()` next to `ent.register_usage_provider(...)`. This makes the COM-04 consumer independent of the import side effect, and is idempotent. It is not required today.
3. **catalog (ADM-41 listing):** `studio_courses` should also list org-private courses of the orgs of the caller's batch grants when the role has `course.edit` (mirror `rbac.service.ORG_PRIVATE_VIA_BATCH`), so trainer-created courses appear in `/trainer/courses`.
4. **web:**
   - Coupons: use `?status=`, read `approval_status`, `required_approver_role` and `expires_at` from the 202 response, and read `approval_request_id` on list rows.
   - Analytics: render `progress_distribution`, `lesson_funnel`, `course_completion_rate`, `test_participation` and the readiness `name` (Insights.tsx, CoordinatorDashboard.tsx).
   - Test builder: add a coding section with a coding-problem picker, and show `batch_id` on tests.
   - Coding: on the attempt page, pass `attempt_id` to COD-03/04/05, run and submit. `codingApi.slugForId` can be dropped.
5. **coordinator:** regenerate openapi (both copies) and the web types. New and changed:
   - coupon `status` query parameter, plus the coupon `approval_request_id` and the 202 fields;
   - `RuleIn.coding_problem_id`, and `"coding"` in `question_types`;
   - test `batch_id`;
   - `attempt_id` on COD-03/04/05 and `RunIn`;
   - the new analytics report fields.
6. **docs:** `role-permission-matrix.md` §2: note that for `course.create/edit` a trainer's batch grant covers the batch org's private courses (the "O-private" cell).
