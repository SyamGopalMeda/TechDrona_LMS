# Dead-code and repo-hygiene removal plan (Firebase stack)

Date: 2026-11-14. **Analysis only: no code was changed.** This is the companion to
`docs/cleanup/feature-removal-plan.md`, which covers whole *features*. This plan covers code and
files that are dead, duplicated or outdated whatever happens to the features.

## Scope and method

**In scope:**
- `apps/lms-spa`;
- `apps/api`, Firestore paths only;
- `functions-lms`, but nothing inside the generated `functions-lms/app`;
- the root Firebase files, `docs/`, `scripts/`, and stray files in the repo.

**Out of scope:** `apps/web`, Postgres, Alembic, the VM deploy (`infra/gcp-demo`, `docker-compose.yml`, Caddy) and `apps/college-data`. These go after the VM is retired. Where an item touches them, it is marked **DEFER-VM**.

**How the evidence was gathered:**

1. **Git state.**
   - `git status` and `git ls-files` were used to tell tracked files from untracked ones.
   - **Most of the live stack is untracked**: `apps/lms-spa/`, `functions-lms/`, `firebase.json`, `firestore.indexes.json`, `qa/`, `docs/firebase/` and about 340 API files.
   - So deleting an untracked file cannot be undone through git. See Batch 0.
2. **SPA reachability.** A small Node script followed every static `import`/`export … from`, every dynamic `import()`, `vi.mock()` and CSS `@import`.
   - It resolved the `@/` and `next/*` aliases from `vite.config.ts`.
   - It started from `src/spa/main.tsx`, where `routes.gen.tsx` lazily imports all 207 pages, plus the modules that `scripts/gen-static.mjs` loads through `ssrLoadModule`.
   - It ran a second time with every `*.test.ts(x)` and `vitest.setup.ts` added as entry points.
   - Result: 769 files in total, 650 reachable from production, 111 tests.
3. **SPA unused exports.** For every named export, the script counted identifier tokens in all the other `src` files, tests included.
   - An export with zero outside mentions is an *unused export*.
   - If the name also appears only once in its own file, the whole symbol is *dead*.
4. **API module reachability.** An AST import graph started from these entry points:
   - `app.main`, `app.worker` and `app.wiring`;
   - every module that is discovered dynamically: `app.modules.*.{models,router,tasks,store_specs,uow_savers}` (from `models_registry._optional_import`, `wiring.py`, `worker.py`, `firestore/backfill`, `identity/fs_uow.py`);
   - `app.seeds.*` and `app.scripts.*`;
   - `functions-lms/main.py`, `lms_edge/*`, `functions-lms/tools/*` and the root `scripts/*.py`.

   String literals of the form `"app.x.y"` counted as references. A second pass added `apps/api/tests/**` as entry points.
5. **API unused functions.** These are top-level, undecorated `def`/`class` names whose identifier occurs only once in the following files:
   - `apps/api/app`;
   - `functions-lms/{main.py,lms_edge,tools}`;
   - the migrations.

   They were then split by whether `apps/api/tests` mention them. Decorated functions (routes and Celery tasks) were skipped. A sample was confirmed with CodeGraph (`codegraph_explore`, which showed no incoming calls) and with grep.
6. **Endpoints.** Every operation in `apps/api/openapi.json` (589) was checked against three sources:
   - the SPA source, excluding the generated `schema.d.ts`;
   - `functions-lms/lms_edge`, `qa/live-e2e` and `apps/college-data`;
   - the API tests.
7. **Config.** Every `Settings` field in `core/config.py` was grepped in the app (outside `config.py`), in `functions-lms/{main.py,lms_edge}` and in the tests. Live values were read from the **non-secret** keys of `functions-lms/.env.billing-f4fe3`.
8. **Indexes.** Each module's `firestore.indexes.fragment.json` was compared with the root `firestore.indexes.json`. Every root `collectionGroup` was grepped in the API code.

**Not run (low RAM):** knip, ts-prune, `vitest`, `pytest` and builds. Every item below lists the tests to run after its removal.

**Confidence:**
- **high**: there are no references, both static and dynamic paths were checked, and it is safe to delete.
- **medium**: the evidence is strong, but runtime, external or owner use is possible. Verify with the tests or the owner first.

## 0. Prerequisites (read first)

**P1. Sync from `apps/web`.**
- `apps/lms-spa/src` is regenerated by `scripts/sync-from-web.mjs`, which wipes `src/` except `src/spa` and copies `apps/web/src` over it.
- I compared 371 non-override files with `apps/web/src`, and all were identical apart from the async wrapping. All 75 `spa-overrides/**` files are byte-identical to their `src/` copies.
- **Any SPA deletion is undone by the next `npm run sync`.**
- So every SPA item below depends on **feature-removal-plan Batch 0**, which retires sync. After that batch, `src/` is the source of truth and `spa-overrides/` (75 files) is deleted. That deletion is already counted in that plan, not here.

**P2. Commit the live stack before deleting anything.**
- The live stack is untracked. Commit it first, together with the `.gitignore` fixes in §3.3.
- Then every removal below is a reviewable, revertible diff.

**P3. Ordering with the feature plan.**
- Run this plan's batches **after feature-plan Batch 1 is merged**, or at least make sure they do not touch the files that plan owns.
- Items in files that the feature plan deletes are listed as *(covered by feature plan)* and are **not** counted here:
  - mentoring;
  - company paths;
  - enquiries;
  - the dead public pages: `features/public/**`, `features/catalog/**` and `features/support/**`;
  - `features/ai/**`;
  - `features/dashboard/**`.
