# Firebase migration: P2 (catalog, content and settings), what was built

Agent: Firebase P2, 2026-11-08. This builds on the P0 store layer (`docs/firebase/p0.md`).
Owner decision F1 applies: only demo data exists, so there is no dual-run. A module moves by
**backfill, then verify, then flip the switch**, and "reseed" is the rollback.
Every switch stays at its default, **`postgres`**.

## 1. Status per P2 module

| Module | State | Switch |
|---|---|---|
| **admin**: `feature_flags`, `policy_settings` | Repository done. The existing tests run on **both** stores. Backfill and verify done. | `TD_STORE_ADMIN` can be flipped once the coordinator has verified it |
| **ai**: `ai_settings`, `app_settings` | Repository done. The existing tests run on both stores. Backfill and verify done. | `TD_STORE_AI` can be flipped once verified |
| **catalog**: courses, versions, modules, lessons, topics, assets, resources | **Data path only**: the data model, mappers, indexes, backfill, verify, and seed→Firestore, all tested on the emulator against the Postgres service output. No repository yet. | **Do not flip** (see §4) |
| admin: privacy_requests, erasure_ledger, retention_policies, break_glass_sessions | Not started (still Postgres) | — |
| ai: ai_usage ledger / quota, ai_tutor_turns | Not started | — |
| media (playback_sessions), notifications, support, orgs | Not started | — |

The switches are per module. Setting `TD_STORE_ADMIN=firestore` moves **only** the flag and
policy tables listed above. The rest of the admin module stays on Postgres. The same applies to
`TD_STORE_AI`.

## 2. Firestore data model

| Collection (document id) | Content | Invariant / note |
|---|---|---|
| `feature_flags/{flag_key}` | The flag row (`id` is kept for the audit `target_id`) | Flags are created only by migrations, then backfilled |
| `policy_settings/{id}` | Every version row, as in Postgres | Versioned and never deleted |
| `policy_heads/{key:scope_type:scope_id\|-}` | `{active_id, version}` | Exactly one active row per key and scope (PG `ux_ps_active`), and a gap-free version. The heads are written in the same transaction as the rows, so concurrent writers on one scope are serialised |
| `ai_settings/platform` | The singleton (PG `id = 1`). If it is absent, the code defaults apply | |
| `app_settings/platform` | `{apps: {key: bool}, updated_by: {key: uid}}` | One read per app-gate check (Spark quota). A missing key means enabled |
| `courses/{id}` | The course row plus `card` (public card fields of the current published version, including lesson_count and duration) and `published_at` | The public listing becomes one query, with no join |
| `courses_by_slug/{org\|platform:slug_lc}` | `{course_id}` | Slug unique per catalogue, case-insensitive (CITEXT) |
| `course_versions/{id}` | The version plus an **embedded outline** (modules → lesson summaries, ordered by position), lesson_count and duration_seconds | A published version is immutable, so the embedded copy cannot go stale |
| `lessons/{id}` | The full lesson plus `course_id` and the embedded `topics` (primary first) | |
| `lesson_assets/{id}`, `resources/{id}` | One document per row | |

The composite indexes and the overrides that disable indexing on large fields (`outline`,
`article_body`, `description_md`, policy `value`) were added to the root
`firestore.indexes.json`. A test checks that the indexes used by the P2 queries are declared,
because the emulator does not enforce indexes.

## 3. Code

| File | What it does |
|---|---|
| `app/core/firestore/store.py` | Adds the following (all system-only except `put`): `ScopedTransaction.put` (a blind upsert for shared and system collections, which is the only kind of write allowed after other writes in a callback), `ScopedStore.scan` / `import_documents` / `delete_all` |
| `app/core/firestore/backfill/` | `TableMapping` + `register_mapping` (SQL table, or a `loader` for assembled documents). `backfill(session, module, replace=)`, `verify(session, module)` (counts, per-document canonical-JSON SHA-256 of the mapped fields, missing/extra/mismatched ids, summed checksum), `sync_if_enabled` (for seeds), and the CLI |
| `app/modules/{admin,ai,catalog}/store_specs.py` | Collection specs plus mappers. The repositories read the same mappers |
| `app/modules/admin/repo_firestore.py` | `AdminSettingsRepo`: flags (list, get, patch in a transaction) and policy (`active_rows`, `history`, `user_exception_count`, `write_version`) |
| `app/modules/ai/repo_firestore.py` | `AISettingsRepo`: settings and apps, read and write |
| `admin/flags.py`, `admin/policy.py`, `admin/router.py`, `ai/store.py`, `ai/router.py` | Dispatch on `uses_firestore(...)`. Response shapes are unchanged: `FlagRow` / `PolicyRow` carry the same attributes as the ORM rows |
| `security/engine.py` | De-join: the HC-01 user-exception count now calls `admin.policy.active_user_exception_count` instead of querying `PolicySetting` |
| `admin/policy.py` | New backend-neutral helpers `active_platform_rows`, `history_rows` and `active_user_exception_count`. `list_settings` makes 2 batched reads instead of about 80 |
| `app/seeds/catalog_demo.py` | After seeding Postgres, it copies the catalogue to Firestore when `TD_STORE_CATALOG=firestore` |

**Authorization.** The routes keep every permission check: `feature_flag.manage`,
`policy.edit` / `policy.propose` with dual control, case decisions for user exceptions, and
step-up.

- **Principal-scoped writes.** The following go through `ScopedStore(principal)`, so the
  store re-checks the permission (defence in depth in place of RLS):
  - flag listing and PATCH (`feature_flag.manage`);
  - AI settings and app PATCH (`feature_flag.manage`).
- **Named system jobs.** Reads that Postgres also did in a system context or with RLS NONE use
  named jobs: `admin.flags`, `admin.policy`, `ai.settings`. Every repository method is
  `@platform_only`, and `assert_repository_scoped` passes for both repositories.

**Cross-store note.** A policy change approved through `approvals` writes Firestore before the
Postgres approval and audit rows commit. If that Postgres commit fails, an orphan version can
remain in Firestore. With demo data only, this is accepted until P6 moves approvals and audit
(outbox saga). The approval id is stored on the row (`approval_request_id`).

## 4. Catalog: why it is not flipped

`learning` (router, service), `media` (router, service) and `paths` (service) read
`courses`, `course_versions`, `lessons`, `lesson_assets` and `resources` through SQL joins
and ORM imports (about 100 references). Flipping catalog alone would leave those modules
reading stale Postgres rows. These steps come next, in order:

1. De-join: give catalog a public read API (`get_course`, `lesson_scope`, `version_lessons`,
   cards), and switch learning, media and paths to it.
2. Write `repo_firestore.py` for authoring:
   - draft clone, outline replace, publish as one transaction (≤ 400 writes; a large outline is chunked by module);
   - the slug reserved via `courses_by_slug`;
   - SoD-04 kept.
3. Matrix-run `tests/catalog`, then flip.

The data model and mappers above are what that repository reads. They are already verified
against `catalog.service` (`tests/catalog/test_firestore_data_path.py`).

## 5. Tests

- `tests/firestore/matrix.py` provides `backend_fixture(*modules)`, a parametrized
  `postgres` / `firestore` fixture. On the Firestore side it:
  1. wipes the emulator;
  2. sets `TD_STORE_<M>=firestore`;
  3. **backfills from the Postgres test DB**, which is the cutover path itself;
  4. restores the switch afterwards.

  It is wired as `admin_backend` / `ai_backend` (`@pytest.mark.usefixtures`) on these tests:
  - the policy bounds, locks, scopes and dual-control tests;
  - precedence and versioning;
  - flags, rollout and allowlist (ADM-17);
  - the cached flag reader;
  - AI settings round-trip, permissions and step-up, app toggles, and `/me/enabled-apps`;
  - all the app-gating tests;
  - the platform AI/app disable test.
- `tests/admin/test_store_parity.py` covers these points:
  - backfill → verify is clean for admin and ai;
  - verify detects mismatched and extra documents;
  - 4 concurrent policy writes get distinct, gap-free versions with exactly one active;
  - history is returned newest first;
  - user > plan > platform precedence, with expired exceptions ignored and locked keys;
  - the store refuses a principal that lacks the permission (content manager);
  - the AI singletons merge;
  - the repository scope lint;
  - the index declarations.
- `tests/catalog/test_firestore_data_path.py` covers these points:
  - the demo seed backfills and verifies on all 6 collections;
  - the card, the embedded outline (order and lesson summaries), the lesson document and the case-insensitive slug index all equal the Postgres service output;
  - backfill is idempotent, and `--replace` reseeds.

Run them with:

```
cd apps/api
TD_TEST_DB_NAME=techdrona_fb_p2 TD_TEST_RESET_DB=1 .venv/Scripts/python -m pytest -q tests/admin tests/ai tests/catalog tests/firestore
```

The emulator starts automatically from the cached jar and stops when the session ends.

## 6. How to flip (after the coordinator has verified)

```powershell
# 1. Firestore reachable (emulator for dev, or the real project + service account in prod)
$env:FIRESTORE_EMULATOR_HOST="127.0.0.1:18080"; $env:FIREBASE_PROJECT_ID="demo-techdrona-lms"
# 2. backfill + verify (reads Postgres via DATABASE_URL, exit 1 on any difference)
cd apps/api; .venv/Scripts/python -m app.core.firestore.backfill admin ai
# 3. set the switches (apps/api/.env or the process env) and restart the API, worker and scheduler
TD_STORE_ADMIN=firestore
TD_STORE_AI=firestore
```

To roll back, set the switch back to `postgres`. Postgres still holds the pre-flip rows, and
any changes made while on Firestore are lost (demo data, per F1). To reseed, run
`... backfill admin ai --replace`. Run `--verify-only` at any time to compare the two stores.

## P2b.2 Catalog

**Public read API (`catalog/api.py`).** It takes the caller's session, so the Postgres SQL and RLS context are unchanged. Joins that crossed modules are split: the caller's own table is queried first, then the catalog rows are batch-loaded, keeping the inner-join filtering and the order.

Functions:
- batch loaders: `get_courses`, `get_versions`, `get_lessons`, `get_assets`, `get_resources`;
- lesson lookups: `find_lessons`, `lesson_with_parents`, `asset_with_parents`, `course_ids_for_lessons`;
- outline and search: `current_outline_lessons`, `search_published_lessons`;
- per-lesson lists: `lesson_assets`, `lesson_resources`;
- scan helpers: `lock_pending_scan_assets`, `assets_by_s3_key`;
- system-context lookups: `course_org_system`, `asset_lesson_id_system`;
- writes: `create_asset`, `update_asset`, `update_lesson`.

Callers: learning (router, service, structured_api), media (router, service), paths, `wiring.py`, analytics (jobs, reports, service) and mentoring.
One API change in media: `apply_scan` was replaced by `scan_changes(result)`.

**Firestore repository.** It returns transient ORM instances, so the serializers and callers are unchanged.

Additions to the data model:
- `courses.draft_version_id` and `courses.last_version_no`, computed by the backfill;
- 4 composite indexes on courses and resources.

New `ScopedTransaction` methods: `get_many`, `query`, `delete_read`.

Invariants:
- **One editable version per course.** It is guarded by `draft_version_id` on the course document. Concurrent clones conflict on that document; a test with two concurrent edits produces exactly one v2.
- **Version numbers** are `last_version_no + 1`, taken inside the transaction.
- **Slugs** are unique per catalogue, case-insensitively, through `courses_by_slug`, reserved and released in the same transaction. A concurrent create gets 409.
- **Publish** is one transaction. It covers:
  - the SoD-04 check;
  - the media-processing and video-missing checks;
  - superseding the previous version;
  - `current_version_id`, the card and `published_at`;
  - clearing the draft pointer.
- **Outline consistency.** Every draft edit and every media `update_lesson` rebuilds the embedded outline, `lesson_count` and `duration_seconds`.
- **Removing a lesson** deletes the lesson and its assets, and sets `resources.lesson_id` to null.
- **Large clones.** A clone over 380 writes is chunked: lessons and assets first, then a final transaction for the version and the pointer.
- **RLS `TN` equivalence.** Reads filter on `app.org_ids` and `app.is_platform`, read from the caller's Postgres session. Writes check the TN WITH CHECK rule. They use `ScopedStore(principal)` when the principal holds the platform-scope permission, and the `catalog.write` job otherwise. Both repositories pass `assert_repository_scoped`.

**Cross-store foreign keys.** The new migrations `learning_0004_drop_catalog_fks` and `paths_0003_drop_lesson_fks` drop 7 foreign keys into catalog tables:
- `enrolments`: `course_id` and `course_version_id`;
- `assignments`: `course_id`;
- `certificates`: `course_id` and `course_version_id`;
- `learning_path_steps` and `learning_path_version_steps`: `lesson_id`.

Without this, a course created on Firestore could not be enrolled in. The columns and indexes stay. Downgrade re-adds the constraints, and a downgrade then upgrade was tested. The matching `ForeignKey`s were removed from `learning/models.py`. **The dev DB needs `alembic upgrade heads`** (the coordinator decides when).

**Tests.** `catalog_backend` (from `backend_fixture("catalog")`) is applied to `tests/catalog`, `tests/media`, `tests/learning` and `tests/paths`. The catalog factory runs `sync_if_enabled(db, "catalog")` after its direct database writes. The new `tests/catalog/test_firestore_repo.py` covers:
- the publish invariants;
- concurrent draft clones;
- slug races;
- outline consistency;
- TN visibility;
- the index declarations;
- the scope lint.

## P2b.3 Notifications and support

- **notifications**
  - `notifications/{uuid7}` is owned by `user_id`, with a TTL `expire_at` of created + 365 days.
  - `notification_dedupe/{sha256(uid,dedupe_key)}` replaces `ux_notif_dedupe` and is created in the same transaction as the notification.
  - Email is sent outside the transaction.
  - Erasure deletes both documents.
  - `core/db.rls_scope` exposes the caller's RLS predicate (RLS family O).
- **support**
  - `support_tickets` and `support_ticket_messages` are owned by `requester_id`.
  - `support_user_notes` is system-family and append-only. `corporate_enquiries` is system-family.
  - Ticket and enquiry numbers come from `tx.next_sequence` on `support_counters/*`. The backfill seeds the counters from the Postgres sequences.
  - `FOR UPDATE` is replaced by a unit of work (`sv.save`) with an optimistic `updated_at` check. A lost race returns 409 instead of waiting on a lock, and auto-close skips such tickets.
  - The open queue is filtered in memory (lane, search and SLA order).
  - De-join: the `admin/accounts.py` dashboard now calls `support.service.dashboard_counts`.
- **Shared store changes** (additive):
  - `array-contains` filter bug fixed;
  - `next_sequence(collection=)` added;
  - `ScopedTransaction.update_read` added;
  - `_stamp_new` keeps an explicit tz-aware `created_at`.

  Also 15 indexes, TTL overrides and large-field overrides were added to `firestore.indexes.json`.

## P2b.4 Known differences. Read these before flipping

1. **Cross-store ordering (catalog, notifications, support).** Firestore commits before the Postgres audit, outbox and idempotency rows, and before the catalog publish hook (`learning.on_course_published`) runs. If the Postgres commit then fails, the Firestore change stays. An idempotent retry can then re-execute it (for example, add a lesson twice). With demo data only this is accepted until P6 (the outbox saga).
2. **Catalog search** is approximated by tokens and substrings, with no websearch OR, negation or phrase semantics. The public, studio and resource lists are keyset scans with in-memory filters, so their cost grows with the size of the catalogue.
3. **`lock_pending_scan_assets`** has no SKIP LOCKED. Two concurrent scan sweeps can emit a duplicate `media.asset_ready`, so run a single sweeper.
4. **Status codes.**
   - Catalog TN WITH CHECK violations return 403 on Firestore (Postgres gives 500).
   - Support races return 409 instead of blocking.
5. **Crash during a chunked clone.** It can leave orphan lesson and asset documents; we believe they are harmless.
6. **Extra Postgres call.** Each catalog read makes one extra Postgres round trip to read the session context.
7. **Backfill overwrites (demo only, F1).**
   - `backfill`/`sync_if_enabled` copies whole collections and overwrites Firestore-only edits.
   - `verify` reports mismatches once data has been edited on Firestore.
   - Never run `sync_if_enabled("support")` after a flip, because it resets the counters.
   - `company_demo.py` writes its enquiry to Postgres only, so backfill support before flipping.

  - Realistically, orgs moves with P5 (identity, rbac, sessions).
