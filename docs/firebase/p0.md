# Firebase migration — P0 foundations (what was built)

Agent: Firebase P0, 2026-11-08. Scope: plan phase P0 only (no module cut over).
Architecture as in `MIGRATION-PLAN.md` Option A: FastAPI keeps the same HTTP API, Firestore is
reached only through the Firebase Admin SDK / async Firestore client from the server,
`firestore.rules` denies every client, and server-side authorization (the `ScopedStore`) replaces RLS.

## 2. The store layer: `app/core/firestore/`

| Module | What it provides |
|---|---|
| `backend.py` | `TD_STORE_<MODULE>=postgres\|firestore` (default `postgres`, alias `pg`). Read once per process. An unknown module or value is an error (typo guard). `MODULES` must match `app/modules/*` plus `core` (a test checks this). API: `uses_firestore("catalog")`, `store_backend(m)`, `firestore_modules()`. Pure Python: it loads no google or grpc code |
| `client.py` (**private**) | `make_client()`. When `FIRESTORE_EMULATOR_HOST` is set, it uses anonymous credentials and a `demo-*` project (default `demo-techdrona-lms`); it refuses the emulator in production. Otherwise it uses a Firebase Admin app built from `FIREBASE_SERVICE_ACCOUNT_FILE` + `FIREBASE_PROJECT_ID`. Also has `get_client` / `set_client` / `close_client` / `aclose` |
| `collections.py` | `register_collection(CollectionSpec(name, family, owner_field="user_id", read_permission, write_permission, owner_writes, append_only, ttl, schema_version))`. Families: `owned` (RLS O/U/US), `shared` (T/TN), `system` (named jobs only). A store call on an unregistered collection fails |
| `store.py` | `ScopedStore(principal)` / `ScopedStore.system("job.name")` (see below) |
| `ids.py` | `compose_id(*parts)`: deterministic, escaped, unambiguous IDs, for example `{uid}:{courseId}`. `hashed_id(ns, value)`: a SHA-256 ID for emails, phones and tokens |
| `codec.py` | UUID→str, tz-aware datetime→UTC (naive datetimes refused), date→ISO, Enum→value, tuple→list. `Decimal` is refused (money is integer paise) |
| `repository.py` | `FirestoreRepository` base class, `@platform_only(permission)`, and `assert_repository_scoped(RepoCls)`: every public async method must take `user_id` or be `@platform_only` (plan §1.4 #2) |
| `checks.py` | The startup gate |

What `ScopedStore` (in `store.py`) does:

- **Store construction.** There is no unscoped store. Every store is built from a `Principal` or from a named system job.
- **Reads.** `get`, `get_many` (batched 100 at a time, as the replacement for joins), `query` and `count`. A document the caller may not see returns `None` or raises `NotFoundError`, so there is no existence oracle. For `owned` collections, a query must name the `user_id`; reading other users' rows needs the spec's `read_permission`, checked through `app.core.auth.check_permission`.
- **Writes.** `create`, `update` and `delete`:
  - They stamp `created_at`, `updated_at`, `schema_version` and `expire_at` (when the spec has a TTL).
  - A caller cannot plant a row owned by someone else, or re-assign ownership, without `write_permission`.
  - `append_only` collections allow no update at all; only a system job may delete from them.
- **Pagination.** Keyset pagination with the existing HMAC-signed cursor (`app.core.pagination`). The document ID breaks ties. A cursor is bound to its collection and sort order. `Page.meta()` returns the same shape as `page_meta`.
- **Transactions.** `run_transaction(fn)` runs `fn(tx)` with the same scoped `get`, `create`, `update` and `delete`:
  - Writes are capped at 400 per transaction (`TransactionTooLargeError`).
  - **External I/O is forbidden inside the callback**, because it may re-run on retry. `forbid_in_transaction("…")` raises `ExternalIOInTransactionError`. Side effects go in `tx.after_commit(cb)`, which runs exactly once after the commit succeeds.
- **Uniqueness.** `tx.reserve_unique(ns, value, owner=(coll, id))` creates `uniq_<ns>/{sha256}` atomically with the row; `tx.release_unique(...)` frees it. `create` with a deterministic `doc_id` that already exists raises `UniqueViolationError`.
- **Sequences.** `tx.next_sequence(name)` gives gap-free numbers from `counters/{name}` (order, ticket and invoice numbers).
- **Leases.** `claim_lease` / `release_lease` on `locks/{key}` replace advisory locks and `SKIP LOCKED`.

**Boundary lint:** `tests/firestore/test_store_boundary.py` fails if any file under `app/`
outside `app/core/firestore/` does any of the following:

- imports `google.cloud.firestore*` or `firebase_admin.firestore*`;
- imports `app.core.firestore.client`;
- calls `firestore.client()` or `firestore_async.client()`.

`firebase_admin.auth` stays allowed, for P1's ID-token verification.

## 3. Startup gate

`run_startup_checks` checks the following:

- **Every environment:**
  - every `TD_STORE_*` value must be valid;
  - `FIREBASE_SERVICE_ACCOUNT_FILE` must not point inside the repository.
- **Production, when at least one module is on Firestore:**
  - no `FIRESTORE_EMULATOR_HOST`;
  - `FIREBASE_PROJECT_ID` set and not `demo-*`;
  - the service-account file exists.

While no module is on Firestore, nothing new is required (production behaviour is unchanged).

## 4. Running the emulator

Java 21 (`java -version` → 21.0.8) and Firebase CLI 15.34.0 are installed. The emulator jar is
cached in `~/.cache/firebase/emulators/`. No system software was installed.

```powershell
# from the repo root (uses firebase.json ports; demo project = offline, can't touch the real one)
firebase emulators:start --only firestore,auth --project demo-techdrona-lms
# API against it (dev only):
$env:FIRESTORE_EMULATOR_HOST="127.0.0.1:18080"; $env:FIREBASE_PROJECT_ID="demo-techdrona-lms"
# wipe data
curl -X DELETE "http://127.0.0.1:18080/emulator/v1/projects/demo-techdrona-lms/databases/(default)/documents"
```

A lighter option, the Firestore emulator alone (about 300–400 MB of RAM):
`java -Xmx384m -jar ~/.cache/firebase/emulators/cloud-firestore-emulator-v1.22.0.jar --host=127.0.0.1 --port=18080`.

If Java is missing on another machine, run `winget install EclipseAdoptium.Temurin.21.JDK`
(or `choco install temurin21`), then `npm i -g firebase-tools`.

## 5. Tests

`tests/firestore/conftest.py` decides how to reach an emulator:

1. It uses an emulator that already answers on `TD_TEST_FIRESTORE_EMULATOR_HOST`, `FIRESTORE_EMULATOR_HOST` or `127.0.0.1:18080`.
2. Otherwise it starts the cached jar with Java and stops it at the end of the session (`TD_TEST_FIRESTORE_AUTOSTART=0` disables this).
3. If neither works, the emulator tests **skip** with an install hint.

Each test gets its own `AsyncClient` on the project `demo-<TD_TEST_DB_NAME>`, wiped before the
test. The root conftest still migrates the Postgres test database, as for every test.

Run them with:

```
cd apps/api
TD_TEST_DB_NAME=techdrona_fb_p0 TD_TEST_RESET_DB=1 .venv/Scripts/python -m pytest tests/firestore -q
```

The tests cover:

- **Authorization families:**
  - owned rows are invisible to other users;
  - staff need the permission;
  - a caller cannot plant rows for someone else or steal ownership;
  - shared and system families;
  - append-only collections.
- **Uniqueness:** a deterministic ID used twice fails, both outside and inside a transaction. An email reservation is atomic with the row, and release works.
- **Rollback:** a failed transaction writes nothing.
- **Gap-free sequence:** 8 concurrent transactions get exactly 1–8.
- **Retry-safety guard and `after_commit`.**
- **Write cap:** 401 writes are refused.
- **Pagination:** stable with ties, a tampered cursor or one with the wrong shape is rejected, and datetime keys work.
- **Leases.**
- **Repository contract lint.**
- **The switch, the gate, IDs, codec, the boundary lint, deny-all rules and `firebase.json` ports.**

## 6. How later phases use it (P2+)

1. Register the module's collections in `app/modules/<m>/store_specs.py` (`CollectionSpec`, with the family and the permission keys taken from `access.py` / rbac).
2. Write `repo.py` (an interface plus the Postgres implementation, with no behaviour change) and `repo_firestore.py(FirestoreRepository)`. Pick the implementation at startup with `uses_firestore("<m>")`. Add `assert_repository_scoped(Repo)` to the module tests.
3. Uniqueness: use a deterministic `doc_id` (`compose_id`) or `tx.reserve_unique`. Sequences: use `tx.next_sequence`. "One open X per user" becomes an `active_x/{uid}` lock document.
4. Never call Razorpay, email, SMS or Celery inside `run_transaction`. Use `tx.after_commit` or the outbox. Adapters should call `forbid_in_transaction()` at their entry point; this is not wired into the existing adapters yet. Doing so is a P2 task.
5. Add composite indexes to `firestore.indexes.json` per phase, and add a `TD_STORE_<M>=firestore` test matrix.

## 7. Not done in P0 (deliberately left for later)

Findings fixed along the way:

1. **Library bug.** In google-cloud-firestore 2.34, `AsyncTransaction.get(doc_ref)` does `await` on an async generator and raises `TypeError`. The store reads through `client.get_all([ref], transaction=tx)` instead.
2. **Livelock under contention.** The library retries ABORTED transactions immediately, with no backoff. With 8 concurrent increments of one counter, 7 of the 8 failed after 20 attempts on the emulator. `run_transaction` now runs its own loop: one library attempt each time, with jittered exponential backoff (20 ms base, 1 s cap, default 10 attempts). It raises `TransactionContentionError` when the attempts run out. After the fix, 8 concurrent transactions got the numbers 1–8 with no gaps in about 10 s.

Not run: the full 865-test backend suite. Only `tests/core` was run, because the only shared code touched is `startup_checks` and `config`. No module code changed.
