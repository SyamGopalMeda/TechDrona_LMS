# Firebase P1: Google sign-in, Analytics, Hosting showcase

Agent: Firebase P1, 2026-11-08. Plan: `docs/firebase/MIGRATION-PLAN.md` §5. Postgres stays the
database; nothing here depends on Firestore (P0).

Owner defaults used (see "Owner decisions" in the plan): **Google sign-in is for students
only.** Staff (admin, trainer, evaluator, content manager) keep password + TOTP. **The demo
link is a static showcase** on Spark. The full app goes on Blaze later.

## 1. What was built

### Google sign-in (students)

* **Web.** "Continue with Google" appears on `/login` and `/signup`
  (`src/features/auth/components/GoogleSignIn.tsx`, `src/lib/firebase/google-auth.ts`).
  * The Firebase JS SDK (`firebase` 12.x, bundled) loads only when the button is clicked.
  * It tries a popup first and falls back to a full-page redirect. Firebase sign-in uses session persistence.
  * After the LMS answers, the page signs out of Firebase, so no Firebase session is left open.
  * If no account exists yet, a short form asks for name, date of birth, Terms/Privacy consent, the optional consents and, for under-18s, the guardian. There is no password, because Google has already verified the email.
* **Headers.**
  * COOP is `same-origin-allow-popups` on `/login` and `/signup` only (`next.config.ts`). Everywhere else it stays `same-origin`.
  * The nonce CSP adds these hosts **on those two pages only** (`src/lib/security/csp.ts`, `src/middleware.ts`):
    * `script-src https://apis.google.com` (CSP2 fallback; `strict-dynamic` covers CSP3 browsers);
    * `connect-src identitytoolkit/securetoken.googleapis.com`;
    * `frame-src https://<authDomain> https://accounts.google.com`.
* **API.** New endpoint `POST /api/v1/auth/login/google` (`app/modules/identity/router.py` → `login_google`; verifier in `app/modules/identity/google.py`).
  * The Firebase ID token is verified server-side with PyJWT against Google's `securetoken` certificates (cached by `max-age`).
  * Token checks:
    * `alg` must be RS256 and `kid` must match a known certificate;
    * signature;
    * `exp` and `iat`;
    * `aud` must be `techdrona-lms` and `iss` must be `https://securetoken.google.com/techdrona-lms`;
    * `sub` must be present;
    * `firebase.sign_in_provider` must be `google.com`;
    * `email_verified` must be `true`;
    * `auth_time` must be at most 5 minutes old (30 minutes when the request completes a new account).
  * Each token can be used **once**: its SHA-256 is kept for 1 hour, and the endpoint fails closed if the store is down.
  * The rate limit is 30 requests per hour per IP. The existing IP-failure and account back-off gates also apply.
  * After that, the request goes through the **existing** pipeline:
    * `login_attempts` (method `sso`);
    * restrictions and takeover lock;
    * device binding and new-device OTP;
    * MFA (a student with TOTP still gets `mfa_required`);
    * concurrent-session cap;
    * the same `td_session`/device/remember cookies and the same response shape as `/auth/login`, plus `new_account`;
    * audit events `identity.login.google`, `auth.login.succeeded`, `identity.user.signed_up` and `identity.link.google`.
* **Linking** works only by the verified email:
  * Staff accounts are refused with 403 `google_signin_not_allowed`.
  * Deactivated or deleted accounts get 401 `invalid_credentials`.
  * If the matching LMS account has an **unverified** email, Google's proof claims it. The email is marked verified, and the password, sessions, remember tokens and devices created before verification are removed. This stops pre-hijacking.
  * New accounts follow the AUTH-01 rules:
    * the consents `terms`, `privacy_notice` and `core_service` are required;
    * age is taken from the date of birth, and under-18 accounts need a guardian (consent link emailed, status `pending_guardian_consent`);
    * minors cannot grant the adult-only purposes;
    * `account_origin=sso`.
* **No link table / migration.** Accounts are matched by verified email, and the Firebase uid is not stored. Unlinking and "first link" notification emails are follow-ups. They would need a `user_external_identities` table.
* **Not checked:** token revocation (`check_revoked`), because that needs the Admin SDK service account. The one-time-use check and the 5-minute `auth_time` window cover replay.

### Firebase Analytics (GA4)

* `src/lib/firebase/analytics.ts` and `src/components/shell/AnalyticsBridge.tsx` (mounted in the root layout).
* **It loads only after the learner grants the existing `analytics_product` consent** ("Product analytics" in Settings › Privacy). Minors cannot grant it.
  * Before that, no script, cookie or request is made.
  * The browser keeps a marker (`localStorage td.analytics_consent`). It is refreshed from `GET /me/consents` once per tab on `/app/*`, and cleared on withdrawal and on sign-out. On withdrawal, `_ga*` cookies are deleted and collection is disabled.
* Consent Mode v2: only `analytics_storage` is granted, and all `ad_*` signals stay denied. Google signals and ad personalisation are off. There is no automatic page_view.
* Events:
  * `page_view`, with ids and tokens replaced by `:id` and no query string;
  * `course_view` (`/courses/<slug>`);
  * `sign_up` (method `password` or `google`);
  * `login` (google);
  * `purchase` on the order page when COM-05 reports `paid` (`transaction_id`, `value`, `INR`).
* Parameters are allow-listed, and any value that looks like an email or phone number is dropped.
* Never on: exam, attempt and test pages; guardian-consent, verify and reset links; or the admin, finance, security, studio, trainer, evaluator, mentor and desk consoles.
* The CSP adds the googletagmanager, google-analytics and firebase(installations) hosts site-wide, only when analytics is configured.
* The consent text for "Product analytics" now says it is measured with Google Analytics.

### Kill switches (runtime: restart, no rebuild)

* `TD_GOOGLE_SIGNIN_ENABLED=false`: hides the button and makes the API return 503 `google_signin_unavailable`.
* `TD_FIREBASE_ANALYTICS_ENABLED=false`: Analytics is never loaded and its CSP hosts are dropped.
* Empty `NEXT_PUBLIC_FIREBASE_*` values turn both off.

The web reads the Firebase config at **request time** on the server and passes it as props. So a running server picks up changes on restart, without a rebuild. The values are public, not secrets.

### Static showcase (Firebase Hosting, Spark)

* `apps/web/scripts/build-showcase.mjs` snapshots the public pages from a running LMS web server (default: the dev stack on `http://localhost:13000`, which holds the seeded catalogue). It writes them to `apps/web/out/showcase/` (git-ignored).
  * Pages: home, `/courses` (with each course page found there), `/pricing`, `/placement`, `/companies`, `/free-resources`, `/enquiries`, `/help` and `/help/grievance`, `/legal/*`, plus a 404 page and `/demo`.
  * **All scripts are removed.** React's streamed Suspense segments are applied statically, so the content is visible without JavaScript. There is no hydration, no API call and no cookie.
  * Because there are no scripts, the hosting CSP can be `script-src 'none'`. The plan's `'unsafe-inline'` exception is not needed.
  * Every page shows a demo banner.
  * The **enquiry form is replaced** by a "this demo can't send the form: email info@techdrona.com" notice with a `mailto:` link.
* `firebase.json` → `hosting` (edited from P0's placeholder; the rest of the file is untouched):
  * `public: apps/web/out/showcase`, with `cleanUrls`;
  * `/login`, `/signup`, `/app/**`, the staff portals, `/verify/**`, `/status` and `/api/**` redirect to `/demo` ("this part needs the full app");
  * strict static security headers, `X-Robots-Tag: noindex`, and immutable caching for `/_next/static/**`.
* Limits:
  * Interactive widgets (the mobile menu toggle, the course filter) do not work in the snapshot. The course search form submits, but always shows the full list.
  * Course data is whatever the source server shows at build time.

## 2. What the owner must do in the Firebase console (project `techdrona-lms`)

1. **Authentication › Sign-in method › Add new provider › Google**: enable it, and set the public-facing name "Tech Drona" and the support email. Keep **email enumeration protection** on (Authentication › Settings).
2. **Authentication › Settings › Authorized domains**: `localhost` is there by default. Add:
   * `techdrona-lms.web.app` and `techdrona-lms.firebaseapp.com` (normally present already);
   * the real LMS domain when it exists (for example `lms.techdrona.in`);
   * any custom demo domain.

   The dev stack runs on `localhost:13000`, which is covered by `localhost`.
3. **Google Cloud console › APIs & Services › Credentials › Browser key (auto created by Firebase)**: restrict it by HTTP referrer to `http://localhost:13000/*`, `https://techdrona-lms.firebaseapp.com/*`, `https://techdrona-lms.web.app/*` and the LMS domain. Restrict its APIs to Identity Toolkit, Token Service, Firebase Installations and Firebase Analytics/Management.
4. **Analytics**: confirm Google Analytics is enabled for the project. The measurement id `G-BXZ1X5KHVC` is already in `.env`. In GA4 (Admin):
   * **Data collection**: turn Google signals off;
   * **Data retention**: 2 months;
   * **Ads personalisation**: off;
   * leave **Enhanced measurement** page views off or ignored (the app sends its own `page_view`).
5. Optional: the OAuth consent screen (Google Cloud › APIs & Services › OAuth consent screen). Set the app name, logo, `https://techdrona.in` and the privacy policy URL, so the Google popup shows Tech Drona branding.
6. Rebuild/redeploy the API image once: it now needs `pyjwt[crypto]` (`apps/api/pyproject.toml`). Rebuild the web image too: it needs the `firebase` package and the new code. Until then the running dev containers do not have the feature.

## 3. Deploy the showcase (owner; not run by the agent)

The LMS dev stack must be running (`http://localhost:13000`). From PowerShell:

```powershell
cd "D:\company website\techdrona LMS\apps\web"
npm run build:showcase          # = node scripts/build-showcase.mjs  -> apps/web/out/showcase
cd "D:\company website\techdrona LMS"
firebase login                  # once, opens the browser
firebase deploy --only hosting --project techdrona-lms
```

* Result: `https://techdrona-lms.web.app` (and `https://techdrona-lms.firebaseapp.com`).
* Preview without replacing the live site: `firebase hosting:channel:deploy preview --project techdrona-lms --expires 7d`.
* Local check: `firebase serve --only hosting --project techdrona-lms`.
* A different source server: `node scripts/build-showcase.mjs --source http://localhost:3000`. The contact email and live link can be set with `TD_SHOWCASE_CONTACT_EMAIL` and `TD_SHOWCASE_LIVE_URL`.
